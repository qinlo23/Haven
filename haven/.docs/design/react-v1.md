# Haven 显式 ReAct 首版设计

状态：四步均已完成；独立入口已切换到显式 StateGraph，MDA 路径保留。

## 1. 目标与当前基线

迁移前的 `haven.py` 通过 `create_agent` 装配独立 Agent，已有本地多轮会话、
进程内检查点和人工批准/拒绝。现在已按照本文设计切换为显式 StateGraph，
保留会话和 CLI 接口；`agent.py`、MDA 连接器、身份声明和启动命令保持不变。

首版只实现一个高血压业务 Agent 和一种 ReAct 范式，不增加意图分类模型、
规划器、反思模型、多 Agent 调度、外部 MCP、HTTP 服务或持久检查点。

ReAct 的逻辑是「思考 → 行动 → 观察 → 再次思考」。观察是确定性地收集工具
结果，不是额外调用模型，也不要求模型生成或存储思考过程文本。

## 2. 模块职责与工厂接口

| 模块 | 职责与接口 |
| --- | --- |
| `haven.py` | 保留 `create_haven(model=None)`、`HavenSession.send()`、`SessionReply`、`run_once()` 和 CLI；装配顶层图、项目级策略与检查点 |
| `agents/hypertension.py` | 提供 `build_hypertension_agent(*, model)`；装配 instructions、现有 11 个工具、业务中间件和审批规则，返回编译后的业务子图 |
| `reasoning/react.py` | 提供 `build_react_graph(*, model, tools, system_prompt, model_middleware, tool_middleware, approval_rules, max_model_calls=8, fallback_reply)`；返回编译后的通用 ReAct 子图 |

`reasoning` 不直接导入 `application/`、`storage/`、`safety/`、项目配置或工具
权限表。业务 Agent 将固定降级文案、模型层和工具层中间件，以及从
`tools/permissions.py` 推导的敏感工具配置作为依赖传入。

首版只支持异步执行。模型中间件使用 `awrap_model_call`，工具中间件使用
`awrap_tool_call`；不实现通用生命周期钩子系统或范式注册中心。

创建顺序：加载配置 → 创建模型 → 构建业务子图 → 构建顶层图 → 编译。
节点执行时复用已有模型、工具与子图，不调用 `create_agent`，不再次创建 Agent。
不在模块导入时创建模型或启动服务。第一版保持当前每个 `HavenSession` 创建
一次独立图实例的方式，不引入跨会话的模块级状态缓存。

## 3. 图结构和状态

顶层图只有两个节点：

```text
START → entry
          ├─ 急救/命令已回复 → END
          └─ 未处理 → hypertension（已编译的 ReAct 子图）→ END
```

业务子图：

```text
START → reason
          ├─ 最终回复或达到调用上限 → END
          └─ 工具调用 → review → act
                                  ├─ 本批还有工具 → act
                                  └─ 本批已完成 → reason
```

`hypertension` 作为编译后的子图节点直接挂入顶层图，不用一个外层函数重新
构建或完整重跑 Agent。顶层持有 `InMemorySaver`，子图不配置自己的 Saver，
继承同一线程下的检查点与命名空间。

状态字段使用覆盖更新，只有消息使用 `add_messages`：

| 字段 | 内容与写入者 |
| --- | --- |
| `messages` | 用户、模型和工具消息；各节点只返回新增消息或按原 ID 替换消息 |
| `handled` | 顶层 `entry` 是否已给出确定性回复，用于跳过业务子图 |
| `model_calls` | 本次用户请求已经尝试的模型调用次数；`entry` 清零，`reason` 递增 |
| `pending_tools` | 本次模型输出中按原顺序冻结的工具调用，包含名称、参数和调用 ID |
| `tool_index` | 本批下一个待处理工具的位置 |
| `review_decisions` | 由 `review` 产生、以工具调用 ID 为键的批准/拒绝结果 |

新用户请求进入 `entry` 时清空临时字段，保留历史消息。中断恢复使用
`Command(resume=...)`，不作为新消息提交，不清零计数或审批状态。
本批工具全部完成后，清空工具和审批字段，再进入下一次 `reason`。

基础 system prompt 和健康摘要只存在于模型请求中，不进入 `messages`。
临时工具状态可能含健康数据，仅存在于进程内检查点，不能写入日志或业务审计。

### 各节点约定

- `entry`：对本次用户输入依次执行急救拦截和命令路由。命中返回固定回复，
  不进入业务子图；未命中只设置 `handled=False`，不调用模型。
- `reason`：检查预算，组装 `ModelRequest`，执行模型中间件和一次模型调用。
  无工具调用则结束；有调用则冻结整批调用、重置游标和旧审批，进入 `review`。
- `review`：根据传入的审批规则识别敏感工具；普通工具无需中断。存在敏感
  工具时只读构造中断请求，收到合法决定后才写入审批映射，不产生业务写入。
- `act`：每次只处理游标对应的一个调用；写入一条 `ToolMessage` 并推进游标。
  拒绝项不调用工具；获准项通过工具执行链处理。节点返回后由图保存检查点。

## 4. 中间件适配与工具执行

StateGraph 不会自动识别和运行 `AgentMiddleware`。薄适配层须显式构造请求、
组合异步 handler，复用现有钩子，不复制现有医学、安全或数据库逻辑。

| 位置 | 顺序及终点 |
| --- | --- |
| 顶层 `entry` | `emergency_input` → `command` → 未处理标记 |
| `reason` | `output_safety` → `MemoryInjectionMiddleware(inject_base_prompt=False)` → 绑定工具的模型调用 |
| `review` | `interrupt_on()` 推导的规则 → 原生 `interrupt()` |
| `act` | 批准校验 → `observability` → `consent_policy` → `mcp_policy` → `ToolNode` 实际工具处理 |

顶层 `entry` 通过原生 `ModelRequest`、当前消息和图 runtime 调用原有模型前
钩子；末端 handler 只记录「未处理」并返回空 `ModelResponse`，不能调用模型。
命中时沿用原有急救审计、命令取数和固定文案；两层钩子均透传才进入业务子图。

`reason` 的末端 handler 按中间件最终返回的模型、工具和 system message
执行 `ainvoke`，将结果封装为 `ModelResponse`。只绑定一次调用需要的工具，
不再嵌套 `create_agent` 或另一套 ReAct 循环。模型故障由原有输出安全层降级；
健康摘要读取失败只省略摘要，不删除基础 instructions 或改写历史。

工具执行复用 `ToolNode` 的名称与参数校验、结果转换和原生 `ToolRuntime`
注入。每次调用 ToolNode 只提交一个工具调用：从完整状态派生临时执行视图，
把最新的工具调用 AI 消息副本限制为当前调用，其他运行字段继续传递。
该视图只供 ToolNode 执行，不写回历史；主状态中的原始整批 AI 消息保持完整。
不通过修改 ToolNode 私有方法来选择调用，不让一批调用进入其默认并行执行。

通过 ToolNode 的 `awrap_tool_call` 组合工具中间件，保留当前相对顺序。
进入敏感工具执行链前再次核对 ID 与批准映射，防止绕过 `review` 直接调用
`act`。首版工具返回普通工具结果；不支持工具自行返回图路由 `Command`。

## 5. 人工确认、预算与失败处理

中断值继续使用当前会话认识的结构：`action_requests` 包含名称、参数和描述，
`review_configs` 声明只允许 `approve`、`reject`。敏感调用按原顺序列出，
审批时按这个冻结顺序关联原工具 ID，不能由模型或用户替换 ID、参数、工具名。

恢复输入沿用当前会话的「中断 ID → decisions」映射；每项决定只允许上述
两种类型，数量必须与中断请求完全一致。输入非法时不执行任何工具，终止该
会话并给出固定错误提示。一次批准或拒绝应用于终端显示的本批敏感操作。
普通工具仍按原顺序执行，拒绝敏感工具不代表取消整批普通工具。

批准或拒绝的敏感调用都必须得到匹配原 ID 的 `ToolMessage`，拒绝结果使用
固定中文文案和错误状态。缺少有效批准时返回拒绝结果，不能默认放行。
工具参数错误或未知工具名沿用确定性校验结果。缺失或重复调用 ID 的模型
输出在执行整批工具前终止本轮，不执行其中任何工具，并清理该无效 AI 工具
消息，返回固定降级回复，避免留下无法配对的工具调用历史。

会话继续串行提交；没有待确认操作时 `/approve`、`/reject` 不触发图运行。
待确认时普通消息不进入图，`/cancel` 不代替拒绝。批准恢复前必须先确定性
扫描当次输入：紧急或疑似紧急消息只返回原有固定文案，不调用模型、不恢复
子图、不执行待确认操作，确认状态保留。`/exit`、EOF、Ctrl+C 均不自动批准。

每个新请求最多调用模型 8 次，失败调用也计入预算；命令和急救短路不计入。
每次准备调用模型前检查预算，审批恢复不能重新获得预算。达到上限时直接
返回传入的固定降级文案，不调用模型或新工具。已产生的合法工具调用需先
获得匹配结果，再结束本轮，不能在线程历史中留下未闭合的工具消息对。
图的 `recursion_limit` 继续作为独立的执行保护，不把它等同于模型调用次数。

一个 `act` 只执行一个调用，并在节点返回时同时保存结果和新游标。中断只在
业务执行之前发生，恢复时重放 `review` 不应重放已完成的工具。节点没有自动
重试策略。数据库写入和检查点不是一个事务，进程崩溃或提交后异常仍可能导致
结果未知：不承诺跨故障恰好执行一次，沿用会话失败后停止、核实数据再重启。

已知工具异常由其既有降级机制处理；执行器的其他工具异常转为不含参数或
原始异常文本的固定错误工具结果，不自动重试。图、检查点或状态异常传播到
会话层后停止会话，不把它们误报为健康数据已成功保存。

后续模块的必要验收场景：

- 无工具直接回答；一次或多次工具调用后回答；系统提示不重复、摘要不入历史。
- 工具调用按顺序执行，结果逐项匹配 ID；原生 runtime 注入且不暴露给模型。
- 暂停前不执行本批任何工具；批准执行、拒绝不执行、非法审批不执行。
- 普通与敏感混合批次的审批边界；拒绝结果闭合消息对，模型能继续处理。
- 多轮上下文与请求预算重置；第 8 次调用后工具结果仍完整，随后结束本轮。
- 批准恢复不重置预算，不重新调用上一轮模型，不重复已完成的业务写入。
- 待确认急救短路；重复批准；退出后创建新会话没有旧线程或旧运行中断。
- 模型故障、工具故障、摘要失败、未知工具、无效调用 ID 和检查点异常。
- 原有同意闸门、正常/异常血压记录、过期确认、删除审批和输出过滤继续有效。
- MDA 入口装配和默认中间件行为保持原样；不向真实模型发送测试健康数据。

本设计依据当前锁定依赖的本地接口核对：`ModelRequest`、`ModelResponse`、

- 子图不创建模型、不读取配置、不加载系统提示文件、不访问数据库；调用方
  提供模型、工具、提示和非空 `fallback_reply`。调用预算默认 8，首版拒绝
  重复工具名、错误的审批配置和不支持的同步钩子。
- 调用方应将子图直接挂入编译后的父图，由父图提供检查点与固定线程，并在

  工具返回 `Command` 不会被用于路由父图。

## 9. 顶层入口当前交付

`create_haven(model=...)` 先构建一次高血压业务子图，再编译带 `entry` 和
`hypertension` 两个节点的顶层图。顶层拥有 `InMemorySaver`，子图继承检查点。

`entry` 显式组合原有急救与命令中间件，末端只标记未处理、不调用模型；
命中时直接结束，否则进入业务子图。新请求在此清空临时执行字段并重置预算，
批准恢复直接回到子图审批节点，不重跑入口或上一次模型调用。

`HavenSession` 继续负责串行提交、待确认时的紧急扫描、审批命令、失败后停止
以及关闭追踪，`SessionReply`、`run_once` 与 CLI 用法保持一致。测试父图仍
保留，用于单独验证通用推理和业务装配；真实顶层图测试复用同一组业务场景。

```bash
uv run python -m unittest discover -s tests -v
```

本轮未接入 LangSmith 追踪、外部 MCP 加载、持久检查点、HTTP 服务或新业务
路由；这些能力属于后续独立任务。
