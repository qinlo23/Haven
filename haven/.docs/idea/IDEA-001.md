## 多病种建档改造（待办）

当前建档仅支持高血压；`tools/onboarding.py` 保存档案时会删除该用户全部疾病记录，再写入当前疾病。接入阿尔茨海默病前，应将基础档案与疾病资料分开维护，改为按病种新增或更新，避免更新一种疾病时覆盖另一种疾病；同时调整单病种校验和建档草稿流程。本次只记录问题，不修改建档行为。

## 长期记忆存储接入（待评估）

长期记忆优先在后端代码中通过官方 SDK 接入数据库，封装检索、校验、确认、去重和删除流程；MCP 用于开发调试或只读参考查询，不作为核心记忆读写链路。

- SQL：继续保存已确认的健康档案、血压、用药等权威记录。
- Qdrant：保存记忆摘要及向量，关联原始记录 ID，用于语义检索。
- Neo4j：按需保存用户、家属、疾病、药物等关系，有明确关系查询需求时再引入。

读取时由后端检索相关记忆，经 `middleware/memory_context.py` 组装上下文；写入时由模型提取候选事实，再由业务代码校验、必要时用户确认后保存，并同步相关索引。区分用户陈述、系统推测和失效信息，避免将推测当成事实。更新、删除需同步处理原始记录、图关系和向量。

初期优先接入 Qdrant 语义检索，保留 SQL 为事实来源，Neo4j 按需补充。本次仅记录方案，不修改现有记忆实现，也不使用 MDA 内置共享记忆存储健康数据。
