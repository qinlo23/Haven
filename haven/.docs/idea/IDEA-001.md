## 长期记忆存储接入（待评估）

长期记忆优先在后端代码中通过官方 SDK 接入数据库，封装检索、校验、确认、去重和删除流程；MCP 用于开发调试或只读参考查询，不作为核心记忆读写链路。

- SQL：继续保存已确认的健康档案、血压、用药等权威记录。
- Qdrant：保存记忆摘要及向量，关联原始记录 ID，用于语义检索。
- Neo4j：按需保存用户、家属、疾病、药物等关系，有明确关系查询需求时再引入。

读取时由后端检索相关记忆，经 `middleware/memory_context.py` 组装上下文；写入时由模型提取候选事实，再由业务代码校验、必要时用户确认后保存，并同步相关索引。区分用户陈述、系统推测和失效信息，避免将推测当成事实。更新、删除需同步处理原始记录、图关系和向量。

初期优先接入 Qdrant 语义检索，保留 SQL 为事实来源，Neo4j 按需补充。本次仅记录方案，不修改现有记忆实现，也不使用 MDA 内置共享记忆存储健康数据。

## 一超多强 Agent 格局与模型驱动规划（待评估）

随着模型能力越来越强，Agent 的架构可以从固定工作流编排转向「一超多强」的格局设计：

- **一超**：由一个核心的强力模型（Super Agent）承担整体规划、任务分解和决策调度职责。它负责理解用户意图、制定执行计划、评估子任务结果、并在必要时动态调整策略。
- **多强**：围绕核心规划模型，部署多个专项能力较强的子 Agent 或工具模块，各自负责特定领域（如记忆检索、知识问答、数据校验、外部 API 调用等），接受 Super Agent 的调度并返回结构化结果。

核心思路是将更多的规划任务交给模型本身，而非在代码层面用工作流写死：

1. **动态规划替代硬编码工作流**：不再预定义固定的执行链路（如先 A 再 B 再 C），而是由 Super Agent 根据当前上下文实时生成执行计划，灵活组合子 Agent 能力。
2. **模型驱动的路由与编排**：由模型判断当前任务需要调用哪些子模块、以何种顺序执行、如何处理异常分支，降低代码维护成本，提升系统的泛化能力。
3. **渐进式演进**：初期可在关键决策点引入模型规划，保留部分确定性工作流作为兜底；随着模型可靠性提升，逐步将更多编排权交给模型。

本次仅记录思路，暂不涉及具体实现。
